# self-evolution（技能自进化 · 元规范）

## 依赖（首次使用自动安装）

无外部依赖（纯规则，不执行命令）。配套 `install.sh` 只做基础环境自检。

**首次使用**：先跑 `bash <本skill目录>/install.sh`（幂等；`<本skill目录>` = skill 工具输出里的 `Base directory for this skill`）。

这不是一个按需触发的技能，而是**所有技能在创建、使用、修改、审查全生命
周期都必须服从的元规范**（含本文件自身）：创建/修改/审查时按铁律与红线
自检技能文本；**使用时**把每次执行当测试——踩坑回流、观察收敛、超线触发
重写评估。本规范**按目标态书写，不以「当前能不能做到」打折**；先运行一段
时间，用实际效果校准。

## 输出范式（所有技能统一）

本 skill 的一切对外输出，发出前按 `meta/user-communication` 的原则与禁止写法自检。

## 三条铁律（互相制衡，缺一不可）

### 一、不二过（可靠性：问题必须回流，重复即缺陷）

- 技能的每一次真实执行都是测试。执行中踩的坑（命令失败、环境意外、流程绕路、
  平台行为与预期不符），修完当前问题后回答「对策回流技能了吗」——**形式
  不限**：沉淀可复用规则进自己内部（排障表、命令模板、流程步骤）、重构
  章节、换判定逻辑都可以，**结果论**：下次同类问题不再踩。
- **同一个坑踩第二次 = 技能缺陷**。判断靠技能文本而非记忆：对策已在技能里
  却仍踩坑，是规则**可达性**问题（埋得太深、措辞含糊），修呈现；技能里
  根本没有，是**回流**失败，补规则。
- 回流必须带证据：错误原文关键行、触发环境、验证通过的命令。没有证据的
  规则不许进技能（见第三条）。

### 二、举一反三（泛化性：写原理，不写细节快照）

- 新规则落笔前过「换个细节还成立吗」检验：把具体版本号、路径、参数在脑中
  换掉，规则是否仍指对动作。只在某个具体取值下成立的，必须升格为**判定
  条件**（怎么识别这类情况），而不是记录那个取值。
- **一个细节变化就触发一次技能更新 = 规则过度拟合**。连续两次为同类细节
  打补丁，必须停下来把两次补丁合并成一条带判定逻辑的通用规则，而不是叠加
  第三条。
- 泛化的边界：只在自己技能声明的场景内求通用，不为想象中的场景预留分支
  （那是另一种膨胀）；没有真实案例支撑的「以防万一」不写。

### 三、反裹脚布（精简性：规则靠证据留任，不靠资历）

- 技能的长度必须与信息密度成正比，不与历史累积成正比。每次修改同步做减法：
  合并重叠规则、删除过时规则（上游已修复的环境问题、已下线的平台路径）、
  压缩冗长叙述为表格或一句话。
- 每条规则要能答上「哪次真实失败产生的它」。答不上来的老规则是噪音，审查时
  默认删除；删错了它会以第一次踩坑的方式自己回来（回到第一条）。
- 三条铁律互相制衡：第一条要求加规则，第三条要求减规则，第二条是调和——
  规则越泛，一条覆盖越多，既少犯重复错又不膨胀。加规则前先想能否靠泛化
  吸收，减规则前先确认没有场景还依赖它。

## 稳定周期红线（收敛是硬指标，超线即重写）

- 技能允许磨合期，但必须收敛：随着使用次数增加，新错误的频率应单调下降。
- **红线：使用十几次后仍在频繁出新错 = 实现有结构性问题**（抽象错位、流程
  不成立、场景假设错误），不符合质量要求——继续打补丁是浪费，**停止修补，
  直接重写**。
- 重写不是全盘丢弃：只带走被多次真实执行验证过的规则做种子，其余推倒；
  重写后重新计稳定周期。
- 结构性失效的信号（满足任一，先怀疑该重写而不是该打补丁）：
  - 新错误**不是同一类**——缺规则只会在同类里打转，结构错才会处处漏水；
  - 补丁开始互相冲突，需要特判绕开早期规则；
  - 规则越加越多，错误率却不降（第二条的泛化也救不回来）。

## 修改任何技能时的自检清单（按序过一遍）

1. 这次改动对应哪次真实执行的问题？（无 → 不改，先找真实问题）
2. 新规则过了「换个细节还成立吗」检验吗？（否 → 写成判定条件再落笔）
3. 有没有旧规则被新规则覆盖或取代？（有 → 合并或删除，不许并存）
4. 这次改动删了什么？（合格的修改通常有增有减；只增不减时回头看第 3 条）
5. 技能整体还在收敛吗？（已使用十几次仍频繁出新错 → 停止修补，按稳定周期
   红线评估重写）
6. 正文改完，frontmatter 的 description 还准确吗？（触发词对不上就同步改，
   并跑 YAML 校验）

## 好坏示例

❌ 排障表逐行追加「某月某日 DNS 又解析到坏 IP，记下这个 IP」——IP 轮换后
再坏，第四条、第五条补丁接踵而至（违反二、三条）。

✅ 合并为「DNS 偶发解析到不可达 IP：探活候选 IP 列表，通的临时进 hosts，
用完必删」——一条判定式规则覆盖全部 IP 轮换（满足二），同时删掉原有
逐 IP 条目（满足三）。
